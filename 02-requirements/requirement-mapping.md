# Requirement Mapping

## Problem-to-Requirement Mapping

The identified user problems were translated into business requirements and functional requirements.

| User Problem | User Need | Business Requirement | Functional Requirements |
|---|---|---|---|
| Uncertainty | Timely and reliable information | BR_01 | FR_01, FR_02 |
| Repeated Monitoring | Reduce manual monitoring | BR_02, BR_03 | FR_04, FR_06, FR_07, FR_08 |
| Enrollment Risk | Safer class switching | BR_04 | FR_12 |

## Requirement Logic

The mapping follows the logic:

**User Problem → User Need → Business Requirement → Functional Requirement**

This ensures that the proposed system behaviors are directly connected to the identified user problems.
